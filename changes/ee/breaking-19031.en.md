The Erlang distribution TLS configuration shipped in `etc/ssl_dist.conf` no longer disables peer certificate verification.

The file is used when `cluster.proto_dist` is set to `inet_tls` or `inet6_tls`. Its `server` and `client` entries now both set `{verify, verify_peer}`, the server also requires the peer to present a certificate (`fail_if_no_peer_cert`), and the `client` entry names `client-cert.pem` and `client-key.pem` so that a node can present a certificate when the peer asks for one. The CA named in `cacertfile` is now enforced on both sides.

The certificate chain is verified, but the peer's host name is still not checked against its certificate, so any certificate issued by a CA listed in `cacertfile` is accepted for any node. Give every node certificate a dNSName/iPAddress subject alternative name that matches the node's host part and remove `server_name_indication` from the `client` entry to bind the certificate to the node as well.

A cluster installed from this release, where every node uses the shipped certificates, is unaffected, because they are all issued by the same CA. A cluster that replaced the certificates, or whose nodes do not share a CA, stops connecting after the upgrade: look for `unknown_ca` or `no_client_certificate_provided` in the node logs. This includes a cluster upgraded from a release that shipped a different example CA, so align every node on one CA before the restart. Do not spread that restart over a mixed set of versions either: an older node cannot present a client certificate, so a mixed cluster keeps failing until every node runs the new configuration.

The option file is read by the Erlang VM once, when the node starts, so a node restart is required for the new configuration to take effect. A hot upgrade does not replace the file; a package upgrade replaces it only when it was not modified locally. Set `EMQX_SSL_DIST_OPTFILE` to keep using a custom option file, including one that still disables verification. When `EMQX_SECURITY_PROFILE` is `hardened`, a node refuses to start, or stops during startup, while its distribution option file leaves peer verification disabled; under the `legacy` profile it logs a warning instead.
