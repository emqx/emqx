Fixed two issues in the GreptimeDB connector with write syntax values: a number written to a tag was not stored as its string representation, including floats and tag templates that mix literals with placeholders; and a quoted field value was rejected instead of being written as the string it contains. A tag value is now written as a string unless it is an `i`/`u`-suffixed integer or a boolean from the message payload, and unquoted field values retain their existing typing.

Note: GreptimeDB creates a tag column from the type declared by the first write, so a table whose tag column was created as a number or a boolean rejects the string form until that column is changed.
