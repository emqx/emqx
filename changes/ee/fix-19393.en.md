Fixed an error log on every QoS 1 and QoS 2 delivery to a gateway client that resumed its session.

When message queues or streams were in use, delivering such a message raised an exception inside a
hook callback. EMQX caught it and logged `hook_callback_exception` at error level. Delivery itself
was not affected. Gateway channels that resume a session, such as an MQTT-SN client waking up from
sleep, do not run a session lifecycle hook, so the channel metadata the callback required was never
set for them.
