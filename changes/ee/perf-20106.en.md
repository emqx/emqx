Improved the clean-up of disconnected clients on replicant nodes.

A replicant node removed each disconnected client from the global channel registry with a separate call to a core node, and it ran one such call per scheduler at a time. With a long network round trip to the core nodes, the clean-up could fall far behind after a burst of disconnects or under steady connection churn. Until the clean-up of a client was done, the node rejected a new connection with the same client ID.

A replicant node now removes the disconnected clients from the registry in batches, with one call to a core node for each batch. When that call fails, the node still removes the local state of those clients.
