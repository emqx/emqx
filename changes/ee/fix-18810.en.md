Dashboard single sign-on now completes an OIDC or SAML login only in the browser that started it. EMQX gives each login a value, keeps it in a browser cookie, and matches it when the identity provider sends the browser back. A login that arrives in a different browser signs no one in.

Three notes for operators:

- Open the Dashboard at the address set in `dashboard_addr` before starting an SSO login. The identity provider sends the browser back to that address, and the cookie belongs to it.
- SAML single sign-on now needs an `https` address in `dashboard_addr`. A SAML identity provider sends the browser back with a cross-site form post, and browsers carry the cookie on such a post only over HTTPS.
- If browsers in your setup cannot keep the cookie and SSO login fails, set `skip_login_cookie_check = true` on the OIDC or SAML backend. This turns the browser check off for that backend, so enable it at your own risk.
