Add a data integration for DamengDB (DM8) over ODBC.

The `dameng` connector and action write messages to a DM8 database with a SQL
template. `INSERT` statements must list the target columns explicitly: the
column types are resolved with `describe` when the action is created, and rows
are written with `odbc:param_query`, batched according to `batch_size`.

A connector is configured either with a DSN (`dsn`) or with the
`driver`/`server`/`port`/`charset` fields; at least one of `dsn` and `server`
must be given, and `dsn` takes precedence when both are set. With the DSN-less
form, `driver` is either an ODBC driver name registered in `odbcinst.ini`
(`DM8 ODBC DRIVER` by default) or the absolute path of the driver library (for
example `/opt/dmdbms/bin/libdodbc.so`), and `username` defaults to `SYSDBA`.
With a `dsn`, `username` and `password` are only sent when they are set, so the
credentials of the DSN entry in `odbc.ini` are used by default. There is no
`database` field: DM8 locates the instance by `host`/`port`, and its ODBC driver
ignores the `Database` connection attribute.

Binary, CLOB/NCLOB and interval columns are rejected when the action is created,
because `odbc:param_query` cannot bind them without corrupting the data. A value
that does not fit the declared column size, or a character value containing a
NUL byte, is rejected as an invalid value instead of being silently truncated.

The optional `ssl_path` and `ssl_pwd` fields enable TLS to a DM8 server that has
`ENABLE_ENCRYPT` enabled, by passing the `SSL_PATH` and `SSL_PWD` connection
attributes to the DM8 ODBC driver, which performs the handshake. A certificate
directory is required by the modes that verify certificates: `1` and `2`
(two-way authentication) and `5` (the client verifies the server certificate).
Modes `0` (no encryption) and `4` (encryption without certificate verification)
need no certificates and ignore the attributes, so setting them is safe before
the server is switched to a certificate-verifying mode. `ssl_pwd` is only needed
when the client private key is encrypted.
