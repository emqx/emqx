The `emqx ctl listeners` command now shows how incoming connections ended at accept time on each running TCP and SSL listener.

A new `accept_stats` block lists one counter per line:

- `accepted`: connections that started a connection process.
- `closed_sys_limit`: connections closed because the node ran out of file descriptors.
- `closed_max_limit`: connections closed because the listener reached `max_connections`.
- `closed_overloaded`: connections closed because the node was overloaded.
- `closed_rate_limited`: connections closed by the listener's connection rate limit.
- `closed_early`: connections the client closed or reset before EMQX started to serve them.
- `closed_forbidden`: connections from addresses denied by the listener's access rules.
- `closed_other_reasons`: connections closed for any other reason.

The `shutdown_count` field now prints one shutdown reason per line, in alphabetical order, instead of a single Erlang term.
