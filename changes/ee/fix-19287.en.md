Fixed a GreptimeDB action failure caused by values that do not match the configured write syntax, such as a floating-point value in a field with the `i` suffix. Invalid messages are now counted as failed without blocking the buffer worker. Valid messages in the same batch are still written.

Integer and unsigned-integer values and timestamps are validated against their supported ranges before writing. Integers without an `i` or `u` suffix are written as `float64`, following the InfluxDB line protocol.
