The broker no longer builds and publishes the `$SYS/brokers/<node>/clients/<clientid>/connected` and `.../disconnected` messages when nothing can receive them: no client in the cluster is subscribed to the topic, and the rule engine ignores `$SYS` messages (`rule_engine.ignore_sys_message = true`, the default). This saves about 4% of the broker CPU spent per connection.

A subscriber on the topic still receives the event. With `rule_engine.ignore_sys_message = false` the messages are published as before, so a rule that selects from a `$SYS` topic still sees them. The same applies to the `subscribed` and `unsubscribed` client events, which are off by default.
