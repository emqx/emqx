Listener views now report `resolved_address`: the IP address a listener is actually bound to on this node, alongside the existing `bind` field. `bind` keeps showing the configured value, including the port; `resolved_address` shows the IP the bind resolves to after the security profile or `node.default_listener_address` applies, which can differ from the address in `bind` for a bare-port bind such as `bind = 1883`.

The resolution happens per node, so a cluster where nodes have different address configuration can bind the same listener to different addresses. In that case, `emqx ctl listeners` and the listener status in `GET /api/v5/listeners` report `resolved_address` as `inconsistent` at the cluster level.
