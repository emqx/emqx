Added an MFA enrollment status to the Dashboard API, so the Dashboard can offer two-factor authentication to users who have not enabled it.

The status is returned by `POST /api/v5/login`, `POST /api/v5/login/verify` and `GET /api/v5/current_user`, which needs no user management permission. It is one of `complete` (enrolled and verified), `pending_voluntary` (no MFA and nothing requires it) or `disabled` (opted out, and nothing requires the user to opt back in), and is derived from existing state with no new configuration.

When an account stops meeting its MFA policy after login, for example because `dashboard.default_mfa` or an SSO backend's `force_mfa` was turned on, or an SSO user turned off MFA under `force_mfa`, `GET /api/v5/current_user` ends all of the account's sessions and returns 401 `MFA_SETUP_REQUIRED`. The next login starts the MFA setup.
