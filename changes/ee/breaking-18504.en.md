Changed the default EMQX security profile from `legacy` to `hardened`. Default MQTT and Dashboard listeners now bind to loopback; authentication, authorization, and access-control failures fail closed; unchanged Dashboard default credentials are rejected; outbound TLS verifies peers; missing JWTs are rejected; SAML signatures are required; internal subscriptions are authorized; delayed messages are re-authorized at publish time; ExHook failures deny the hooked action; plugin installation requires a SHA-256 checksum; built-in database authentication defaults to auto-generated passwords with strong hashing; and the node refuses to start with the default Erlang cookie. Set `EMQX_SECURITY_PROFILE=legacy` to retain the previous behavior during migration.
