Reduced the memory and CPU cost of the node-local channel-info table. The table no longer stores a client's will message, its CONNECT properties, or its subscription list. Each client's entry now has a fixed size instead of growing with the CONNECT packet and with the number of subscriptions, and the entry is rewritten on every SUBACK and UNSUBACK.

The REST API responses and the arguments passed to hook callbacks do not change. Plugins that read the table directly, through `emqx_cm:get_chan_info/1,2`, `emqx_cm:lookup_client/1`, `emqx_mgmt:lookup_client/2`, `emqx_channel:info/1` or `emqx_connection:info/1`, no longer see `will_msg`, `conninfo.conn_props` or `session.subscriptions` in the returned map. Use `emqx_broker:subscriptions/1` for a client's subscriptions, the `client.connected` hook for its CONNECT properties, or `emqx_channel:info/2` to read a single attribute from the channel.
