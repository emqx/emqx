The STOMP, NATS and JT/T 808 gateways used to buffer a whole client frame before applying the configured size limits, so a client could make the broker hold an unbounded amount of memory with an unterminated frame or with a payload whose declared size was huge. The limits are now enforced while the frame is parsed: STOMP rejects a declared `content-length` above `gateway.stomp.frame.max_body_length`, NATS rejects declared sizes above `gateway.nats.protocol.max_payload_size`, and the JT/T 808 gateway now enforces `gateway.jt808.frame.max_length`, which was previously ignored.

STOMP transactions no longer retain state indefinitely. A client could open an unbounded number of transactions and buffer an unbounded number of frames in them, and the periodic cleanup never released expired transactions. `gateway.stomp.transaction` now bounds the number of transactions, the actions per transaction, the total retained bytes and the transaction lifetime, and expired transactions are actually removed.

The LwM2M gateway no longer accepts a re-registration that authenticates as a different device. Previously the new identity reused the session already bound to the connection, including its subscriptions, pending commands and protocol state; such a re-registration is now rejected with `4.01 Unauthorized`.
