The LDAP authenticator can now set client attributes from the user's directory entry, so authorization rules can match on LDAP group membership.

Each entry in the new `client_attrs` list reads one directory attribute, such as `memberOf`, and selects one of its values with an ordered list of regular expressions. It then sets the whole value, or the `CN` of a DN value, as one client attribute. Several entries can set attributes for the same client, so a user in two configured groups gets both attributes and the permissions of both groups. For example:

```
client_attrs = [
  {attribute = "memberOf", set_as_attr = "grp_x", select = ["^CN=GROUP-X,"], extract = cn}
  {attribute = "memberOf", set_as_attr = "grp_y", select = ["^CN=GROUP-Y,"], extract = cn}
]
```

A pattern matches the whole attribute value, which for `memberOf` is the full DN of the group. Anchor the pattern as shown: a pattern without anchors, such as `CN=GROUP-X`, also matches `CN=GROUP-X-ADMIN,...`. Matching is case-sensitive; start a pattern with `(?i)` to ignore case.

The new `require_client_attrs` option denies a client for which no entry sets an attribute. It is `false` by default. Nested group membership is not resolved.
