The `authentication_settings.ignore_backend_failures` and `authorization.ignore_backend_failures` settings now apply in both the `legacy` and `hardened` security profiles. Previously they took effect only under the `hardened` profile.

Each setting now accepts three values:

- `per_security_profile` (the new default): Follow the security profile. The `legacy` profile ignores backend failures. The `hardened` profile denies the client.
- `true`: Ignore backend failures and continue to the next authenticator or authorization source.
- `false`: Deny the client when a backend fails.

Upgrade note: under the `legacy` profile, a stored value of `false` now denies the client on a backend failure. Saving the authorization settings through the REST API or the Dashboard in an earlier 6.x release can store `false` even if you did not change this setting. To keep the previous `legacy` behavior, set the value to `per_security_profile` after the upgrade.
