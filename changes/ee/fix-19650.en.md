Fixed a potential leak where reconnect callback functions could accumulate over time for some Actions when their underlying connection would reconnect.

Affected Actions:

- Oracle
- Postgres family (TimescaleDB, MatrixDB, CockroachDB, AlloyDB, Redshift)
- Cassandra
- Datalayers Arrow Flight

Fixed an issue where, after an Oracle Action was deleted or its SQL template changed, the old SQL could still be sent to the database when the connection reconnected, which produced errors such as ORA-00904 in the logs. Reconnect callbacks of removed actions are now cleaned up. The Oracle connector now also reconnects its pool workers automatically and re-validates the configured SQL on every reconnect.
