Fixed the SUBACK reason codes when a `client.subscribe` hook changes the number of topic filters.

A hook returning more topic filters than it was given crashed the connection before any SUBACK was sent. A hook returning fewer could report a removed filter as granted, so the client waited for messages on a subscription that did not exist. When the number changes, each filter passed to the hook now gets the reason code of the subscribed filter with the same topic, or is reported as failed if there is none. Filters the hook added get no reason code, so SUBACK keeps one per requested filter, in the order they were received.
