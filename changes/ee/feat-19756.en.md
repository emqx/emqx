Added the `node.trusted_certs` configuration. It selects the CA certificates that outbound TLS clients trust when their own TLS configuration names no CA. The default `system_default` uses the CA bundle file of the operating system. Set `file:///absolute/path` to use a different PEM file.

An outbound TLS client that sets `verify = verify_peer` and leaves `cacertfile` empty now verifies the server against these CA certificates. Before, such a client failed to connect.

The built-in HTTP client that some integrations use (for example AI Completion, ClickHouse, OpenTSDB, TDengine, Tablestore, HTTP authentication and authorization, and S3) no longer has a CA bundle of its own. It uses `node.trusted_certs` too.

An outbound TLS client can also set `cacertfile = system_default` to trust the CA certificates of `node.trusted_certs`. When `node.trusted_certs` finds no CA bundle file, the client uses the CA certificates that Erlang/OTP loads from the operating system. Listeners do not accept this value.

The Docker image now installs the current Mozilla CA bundle from curl.se at build time.

Relevant PRs: [#19756](https://github.com/emqx/emqx/pull/19756), [#19799](https://github.com/emqx/emqx/pull/19799).
