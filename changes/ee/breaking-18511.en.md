Changed the default EMQX security profile from `legacy` to `hardened`. Default MQTT and Dashboard listeners now bind to loopback; authentication, authorization, and access-control failures fail closed; unchanged Dashboard default credentials are rejected; outbound TLS verifies peers; missing JWTs are rejected; internal subscriptions are authorized; delayed messages are re-authorized at publish time; ExHook failures deny the hooked action; plugin installation requires a SHA-256 checksum; built-in database authentication defaults to auto-generated passwords with strong hashing; namespaced built-in database users cannot conflict with global users; and the node refuses to start with the default Erlang cookie. Existing built-in database authentication configurations with a manually set password hash algorithm remain valid after the upgrade. Set `EMQX_SECURITY_PROFILE=legacy` to retain the previous behavior during migration. To keep the rest of the profile while serving remote clients, set `node.default_listener_address` instead of switching the whole profile.
