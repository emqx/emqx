Added the `node.secret_file_allow_list` setting. It lists the files that a secret can read its value from when the secret is set as `file://<path>`.

- The setting is a list of path patterns, for example `["/run/secrets/**"]`. It can be set only in `emqx.conf` or with an environment variable, and it takes effect when the node starts.
- The default, `["**"]`, allows every path, so existing configs work as before.
- A pattern is compared with the real path of the file, in which symbolic links are resolved. In a mounted secret volume, for example in Kubernetes, each file is a symbolic link to a file in a subdirectory, so use a pattern that ends with `/**` for it.
- When the file of a `file://` secret matches no pattern, EMQX does not read the file. The secret is then empty, an error log names the path, and the alarm `secret_file_read_denied` is raised. Nothing clears this alarm automatically: find the denied reads in the error log, fix the cause, then deactivate the alarm manually.
- A connector, an action or a source in a namespace no longer reads `file://` secrets. The secret is empty, an error log names the path, and the same alarm is raised. Set the value of the secret directly in a namespace. An encrypted TLS private key whose password is a `file://` secret is rejected in a namespace.
- The file that `node.cookie` points to is not read as a secret.
- A connectivity test of a connector, an action or a source (`/connectors_probe`, `/actions_probe`, `/sources_probe`) does not run with an empty secret. It fails with an error that gives the reason.
- The GCP PubSub, BigQuery and Azure Blob Storage connectors check the service account JSON or the account key when their config is checked. For a `file://` value, they now read the file for this check only when the global config is updated or tested. In each other config check, for example when the node starts, the file is not read, and the connector reports an invalid value when it starts.
- The setting does not apply to `license.key`. A license file needs no pattern in the list.
