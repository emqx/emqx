Added OAuth2 client-credentials grant support to the HTTP connector and HTTP authentication/authorization.

The HTTP connector (data integration) and `authn_http` / `authz_http` now accept an `oauth2` configuration block (placed after the HTTP headers) with `client_id`, `client_secret`, `token_endpoint`, `scope`, TLS options, and a request timeout. When enabled, a bearer `access_token` is obtained via the `client_credentials` grant and injected into the `Authorization` header of every outbound request.

A new `emqx_connector_oauth2` application manages the token lifecycle: it fetches and proactively refreshes tokens at 75% of `expires_in`, caches them in a public ETS table keyed by resource id, and shares concurrent cache-miss requests for the same resource. Token requests for different resources run independently.

When OAuth2 is enabled, the HTTP connector health check also probes the token endpoint and reports `disconnected` if it is misconfigured or unreachable. Configurations where `oauth2` collides with a user-provided `Authorization` header are rejected at validation time.
