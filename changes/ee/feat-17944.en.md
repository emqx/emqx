Added OAuth2 client-credentials grant support to the HTTP connector and HTTP authentication/authorization.

The HTTP connector (data integration) and `authn_http` / `authz_http` now accept an `oauth2` configuration block (placed after the HTTP headers) with `client_id`, `client_secret`, `token_endpoint`, `scope`, and a request timeout. When enabled, a bearer `access_token` is obtained via the `client_credentials` grant and injected into the `Authorization` header of every outbound request.

A new `emqx_connector_oauth2` application manages the token lifecycle: a singleton GenServer fetches and proactively refreshes the token (at 75% of `expires_in`), caching it in a public ETS table keyed by resource id so the HTTP connector reads the token from ETS before each request without blocking on the token endpoint. The GenServer state stores only plain fetch parameters (the refresh logic lives in a named function), so a hot code upgrade picks up the new logic.

When OAuth2 is enabled, the HTTP connector health check also probes the token endpoint and reports `disconnected` if it is misconfigured or unreachable. Configurations where `oauth2` collides with a user-provided `Authorization` (or other OAuth2-reserved) header are rejected at validation time.
