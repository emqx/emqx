Added the `rpc.compress_level` and `rpc.compress_threshold` settings to compress the data that cluster nodes send to each other, including forwarded MQTT messages.

`rpc.compress_level` sets the zlib level, from `1` (fastest) to `9` (smallest output). The default is `0`, which disables compression, so nothing changes on upgrade. `rpc.compress_threshold` sets the minimum packet size to compress and defaults to `1KB`.

Compression uses CPU on both the sending and the receiving node to reduce the traffic between them. Enable it when the bandwidth between nodes is limited or billed, for example when a cluster spans availability zones. Level `1` gives most of the size reduction at the lowest CPU cost. For JSON payloads of 0.5 to 1 KB, level `1` reduced the traffic between nodes by about 60% and raised CPU usage by about 10% on the sending node and 5% on the receiving node. Payloads that are already compressed or encrypted do not get smaller, so for them compression only adds CPU cost.
