Release `emqx_bcast` 0.4.5 as a follow-up to 0.4.4, which ships with EMQX
6.3.3. This release contains QoS 1 BatchPub recovery and accounting fixes.
`PendingCount` now decreases after a partial acknowledgement. An
unacknowledged delivery is retried after a clean-session reconnect, and
persisted ACK accounting is recovered after an index owner handover. A missing
remaining-ack counter is rebuilt by the next completed-part report.

Partial ACK markers are coalesced per delivery and index shard into a 500 ms
flush. This removes a replicated Mnesia write from every acknowledgement and
keeps acknowledgement accounting within the pull side's recovery window. Each
unfinished part now replaces its previous marker, while a completed part keeps
only its durable accounting watermark and counter decrement. The ACK-worker
backlog now uses a constant-time queue, and expired ACK-in-flight warnings are
aggregated per sweep.

Plugin-generated 429 responses now write throttled warnings with request and
quota details. Invalid plugin configuration values are rejected at write time.
A client that connected before the plugin started is armed by a verified local
subscription event instead of waiting for keepalive or another publish.
Message expiry remains monotonic when identical-content or reused-MessageId
requests are promoted out of order, including when they share one promotion
batch.

Different versions of the `emqx_bcast` plugin are not supported in one cluster.
Upgrade it cluster-wide by uninstalling the old version and installing the new
version. For an EMQX rolling upgrade, stopping the plugin on every node before
the upgrade and enabling it after all nodes have been upgraded is a recommended
operational procedure, not a plugin compatibility requirement.
