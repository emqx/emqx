Release `emqx_bcast` 0.4.5 as a follow-up to 0.4.4, which ships with EMQX
6.3.3. This release contains QoS 1 BatchPub recovery and accounting fixes.
`PendingCount` now decreases after a partial acknowledgement. An
unacknowledged delivery is retried after a clean-session reconnect, and
persisted ACK accounting is recovered after an index owner handover. A missing
remaining-ack counter is rebuilt by the next completed-part report. Completed
parts and partial ACKs from unfinished parts are projected separately, so a
completed device does not reappear in the pending count.

Partial ACK markers are coalesced per delivery and index shard into a 500 ms
flush. This removes a replicated Mnesia write from every acknowledgement and
keeps acknowledgement accounting within the pull side's recovery window. Each
unfinished part now replaces its previous marker, while a completed part keeps
only its durable accounting watermark. New deliveries route those completed
parts by DeliveryId to reporter workers, which project the remaining count and
run one completion transaction per delivery rather than one transaction per
index-shard part. A persisted partial ACK is counted once when its part
completes, and owner handover retains the full part size for recovery. Unique
per-part device and ACK sets prevent a promoter retry from counting an
already-ACKed device twice. Source shards notify reporters asynchronously,
retry until acknowledged, and monitor the acknowledged reporter process. Once
the account row is durable, buffered and persisted partial ACK state for that
completed part is cleared. Reporters use an O(1) target lookup, normalize
legacy remaining meta counters to the full target, retry Mnesia replica
visibility with exponential backoff capped at five seconds, and do not treat a
local miss as deletion until all running DB cores agree. Delivery deletion
sends an explicit forget, with a bounded sweep as a lost-notification backstop.
A reporter that loses a counter-projection race with delivery deletion rechecks
metadata after writing and removes the newly recreated counter row.
Index rebuilds consolidate persisted partial-ACK markers and restore the exact
row that the next flush replaces, so completed parts do not accumulate stale
bag rows. Orphan accounting cleanup retries a failed bounded slice before
advancing its rotating scan.
The ACK-worker backlog now uses a constant-time queue, and expired
ACK-in-flight warnings are aggregated per sweep. Marker flushes use an O(1)
local existence check, so their Mnesia read volume no longer grows with drain
duration.

Plugin-generated 429 responses now write throttled warnings with request and
quota details. Invalid plugin configuration values are rejected at write time.
A client that connected before the plugin started is armed by a verified local
subscription event instead of waiting for keepalive or another publish.
When a resumed session adopts a new channel PID, cached subscription filters
remain available while EMQX completes the restored subscription record, so a
transiently incomplete broker read cannot stall the client's QoS1 backlog.
Message expiry remains monotonic when identical-content or reused-MessageId
requests are promoted out of order, including when they share one promotion
batch.

Different versions of the `emqx_bcast` plugin are not supported in one cluster.
Upgrade it cluster-wide by uninstalling the old version and installing the new
version. For an EMQX rolling upgrade, stopping the plugin on every node before
the upgrade and enabling it after all nodes have been upgraded is a recommended
operational procedure, not a plugin compatibility requirement.
