Fixed an issue where resetting a topic-metrics collection could reset the counters on some cluster nodes only when audit logging is enabled.

The reset operation emitted a malformed audit event. Writing the event to the audit database failed and broke the cluster-wide replication of the reset, while the REST API still returned success. The audit event is now well formed and appears in the audit log with `from` set to `cluster_rpc`. In addition, a failure to write an audit record to the database no longer interrupts the audited operation itself; the failure is logged instead.
