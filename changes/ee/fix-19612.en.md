Fixed will message handling for an MQTT 5.0 client that is re-authenticating with an AUTH packet. Before this fix, the will message of such a client was not published when the client was kicked, when a new connection with Clean Start = 1 discarded the session, or when a new connection with the same client ID took over the session while the Will Delay Interval or the Session Expiry Interval was 0. When the connection closed during re-authentication, the will message was not published after the Will Delay Interval. The will message now follows the same rules as for a connected client.
