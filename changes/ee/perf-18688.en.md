The number of dirty I/O scheduler threads (`+SDio`) can now be configured via `node.dirty_io_schedulers`, and defaults to tracking `node.schedulers` instead of a fixed 8. On small nodes (for example, a 2 vCPU container or cgroup, where `node.schedulers` already auto-resolves to 2), this avoids spawning dirty I/O scheduler threads the node has no CPU capacity to run in parallel, reducing boot-time memory footprint.
