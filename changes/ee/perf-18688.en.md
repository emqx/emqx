The number of dirty I/O scheduler threads (`+SDio`) can now be configured via `node.dirty_io_schedulers`. The default `auto` keeps the previous fixed value of 8 on nodes where `node.schedulers` resolves to more than 2, and uses 4 on smaller nodes (for example, a 2 vCPU container or cgroup). This reduces boot-time memory footprint on small nodes while keeping enough threads to overlap blocking I/O operations.
