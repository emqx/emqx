Data backup exports now record the exporting node's security profile.

Restoring a backup that was exported under the `legacy` security profile onto a node running the `hardened` security profile can leave listeners bound to loopback only, because a bare-port bind (for example `bind = 1883`) resolves differently under each profile. Such an import is now refused, so an operator does not restore a backup and lose external connectivity without a warning. Pass the `--allow-security-profile-mismatch` CLI flag, or the `allow_security_profile_mismatch` API parameter, to import anyway. A backup that predates this change is treated the same as one exported under `legacy`. Restoring into a node running `legacy` is never affected.
