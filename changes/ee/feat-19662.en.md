Added the `consume_message` option to rules, `false` by default. When a rule with the option selects a message, that is, its `FROM` clause matches and its `WHERE` clause is true, the message is marked as consumed. A consumed message that matches no MQTT subscriber is treated as delivered: MQTT 5.0 publishers receive reason code 0x00 (Success) instead of 0x10 (No matching subscribers) in PUBACK and PUBREC, and the message is not counted in `messages.dropped` and `messages.dropped.no_subscribers` and does not trigger `$events/message_dropped`. It is counted in the new `messages.consumed` metric instead, exported to Prometheus as `emqx_messages_consumed`. Delivery to matching subscribers does not change.

ExHook servers can mark a message as consumed too, by returning the `consumed` header as `"true"` from `OnMessagePublish`.
