Fixed an issue where a GreptimeDB action could stop writing data after receiving a message whose value did not match the type declared in the write syntax, such as a float in a field with the `i` suffix. Previously, rendering such a value raised an exception that was treated as retryable: the whole batch remained in the inflight queue, the affected buffer worker stopped sending messages assigned to it, and those messages accumulated until they expired, potentially increasing memory or disk usage. Invalid messages are now dropped and counted as failed; when batching is enabled, valid messages in the same batch are still written, and the affected buffer worker continues processing subsequent messages.
