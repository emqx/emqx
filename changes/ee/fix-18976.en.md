Fixed an issue where a GreptimeDB action could stop writing some or all data after receiving a message containing a value that did not match the configured write syntax, such as a floating-point value in a field with the `i` suffix. Previously, the conversion error was treated as retryable, so the affected batch remained in the inflight queue and was retried until its messages expired. This prevented the affected buffer worker from sending later messages and could cause queued messages to consume a large amount of memory or disk space.

Invalid messages are now dropped and counted as failed. Valid messages from the same batch are still written, and the buffer worker continues processing later messages. Values using the `i` or `u` suffix and message timestamps are checked before they are sent, preventing out-of-range values from overflowing or being stored incorrectly. Integers without an `i` or `u` suffix are now written as `float64`, in accordance with the InfluxDB line protocol, instead of being interpreted as Unicode characters.
