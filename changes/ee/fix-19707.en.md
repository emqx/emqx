Fixed GreptimeDB connector write syntax values taking the line protocol `i`/`u` type suffix from
text rendered by a placeholder. The suffix now comes only from a value that is exactly one
placeholder followed by a literal `i`/`u` token, so `tag=${n}${suffix}` with `suffix` = `i` stores
the string `65i` instead of the integer `65`, and a non-integer payload in that form no longer fails
the point. A literal suffix such as `${n}i` still declares `INT64`/`UINT64`, and a fully literal
`65i` stays a string, unchanged by this fix.

Note: GreptimeDB derives a column's type from the first write and the type of a tag (primary key)
column cannot be changed afterwards with `ALTER TABLE ... MODIFY COLUMN`. A table whose column was
created from a placeholder value by an earlier version (for example an `INT64` tag column) keeps
rejecting the string form; write to a new measurement so that the column is created with the
intended type. Existing rows are not rewritten.
