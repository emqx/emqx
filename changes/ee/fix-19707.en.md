In the GreptimeDB connector, write syntax values now take the line protocol `i`/`u` type suffix
only from a separate literal `i`/`u` token that directly follows a value placeholder, so the same
text contributed by a placeholder stays text: `tag=${n}${suffix}` with `suffix` = `i` stores the
string `65i` instead of the integer `65`, and a non-integer payload no longer fails the point. A
literal suffix such as `${n}i` still declares `INT64`/`UINT64`, and a fully literal `65i` stays a
string.

Note: GreptimeDB derives a column's type from the first write and the type of a tag (primary key)
column cannot be changed afterwards with `ALTER TABLE ... MODIFY COLUMN`. A table whose column was
created by the previous, ambiguous form (for example an `INT64` tag column) keeps rejecting the
string form; write to a new measurement so that the column is created with the intended type.
Existing rows are not rewritten.
