Added the `mqtt.stats_emit_interval` option for the statistics timer of a connection. The default is 60 seconds.

Before, the timer used `mqtt.idle_timeout` (default 15 seconds). With the new default, an active connection does this work one quarter as often. These changes are visible:

- The REST API and the Dashboard update the byte counters (`recv_oct`, `send_oct`), `send_pend` and the session gauges (for example `mqueue_len` and `inflight_cnt`) of a connected client every 60 seconds instead of every 15 seconds. The packet and message counters do not change. They still update when a packet arrives or leaves.
- The congestion alarm and the session buffer high watermark log can occur up to 60 seconds after the condition starts.
- A change of the limiter configuration can take up to 60 seconds to apply to the existing connections.

`mqtt.idle_timeout` now only sets the time that a new connection can stay without a CONNECT packet.
