Reduced the CPU cost of handling PUBLISH packets.

- When the `socket` TCP backend is in use, each packet read now needs one receive call instead of two.
- Topic splitting and topic validation do less work for each message.
- The Sparkplug B alias-mapping hook checks the topic first. It does no more work for topics outside the Sparkplug B namespace.
- The A2A registry, schema validation, message transformation and legacy topic metrics add their message hooks only when the feature is first used. Before that, they add no cost to each message.
- When no rate limit is configured for a client, the limiter configuration is not checked on each publish.

In a test with 60,000 clients that each publish one 1 KB QoS 0 message per second, broker CPU usage dropped by about 10% with the `gen_tcp` backend and by about 24% with the `socket` backend.
