Fixed client certificate information being lost when a proxy terminates mutual TLS and re-encrypts the connection to EMQX. When a listener has `proxy_protocol = true` and the PROXY protocol v2 header carries SSL TLVs, EMQX now reads the client certificate details from the header. It reads the certificate from its own TLS session only when the header carries no certificate information. Before this change, a listener with TLS enabled always read its own TLS session, so a deployment that forwards the client common name through HAProxy lost it after an upgrade from 5.x.

Also fixed several listener socket option problems: `v6only` and `{tune_buffer, false}` are now handled correctly, invalid socket tuning options are rejected instead of applied, and a fragmented PROXY protocol v1 header is now rejected instead of being parsed incorrectly.
