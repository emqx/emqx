Fixed an issue where a subscription to a Message Queue topic (`$queue/<name>` or `$q/<topic filter>`) could receive no messages after a node restart. A client that subscribed while the Message Queue subsystem was still starting got a successful SUBACK, but the subscription was not attached to the queue. Each subsequent subscription to a Message Queue topic on the same connection was refused, and only a new connection recovered.

Now EMQX refuses such a subscription with the `Not authorized` (0x87) reason code until the Message Queue subsystem is started. The client can send the subscription again on the same connection.
