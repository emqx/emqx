A malformed `Authorization` header now returns 401 `AUTHORIZATION_HEADER_ERROR` instead of a bare 400, and its content is no longer written to the error log.

Credentials that the HTTP specification cannot parse, such as Basic credentials without the `:` separator or a Bearer token with an invalid character, previously made the request process exit. The crash report that followed held the header value at error level, so a client with a formatting mistake wrote its own credential to the log, and an unauthenticated caller could add a log entry of its own choosing on every request.
