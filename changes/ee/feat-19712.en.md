Added support for JWT as an MQTT 5.0 enhanced authentication method, so a connected client can renew an expiring token in-session instead of reconnecting.

* A client connecting with `Authentication Method` set to `JWT` passes its token in `Authentication Data`. The token is validated in a single round, with no challenge from the broker.
* A client that selects the `JWT` method and sends no `Authentication Data` is denied. The `on_missing_jwt` setting applies only to a token in the username or password field.
* Sending an `AUTH` packet with reason code `0x19` and a fresh token refreshes the authorization context (`acl`, `is_superuser`) and pushes out the disconnect deadline, keeping the session, subscriptions, client ID and username.
* The authentication method is fixed for the session, so a client that connected with a password cannot switch to `JWT` re-authentication.
* For every enhanced authentication method, a successful re-authentication replaces the ACL rules of the previous credential. When the new credential carries no ACL rules, the previous rules are removed.
* For every enhanced authentication method, a re-authentication sets a new disconnect deadline from the expiry of the new credential. When the new credential has no expiry, the client is no longer disconnected at the deadline of the previous credential.
* For every enhanced authentication method, the client attributes and client ID set at CONNECT hold for the life of the session. A re-authentication result cannot change the client attributes. A re-authentication result with a `clientid_override` that differs from the current client ID fails, and the client is disconnected with reason code `0x87` (Not authorized).
* A successful re-authentication with any enhanced authentication method clears the client's authorization cache, so the new permissions apply to the next publish or subscribe.
* Fixed the connection authentication expiry timer not being re-armed after a successful re-authentication, which disconnected clients at the deadline of their previous credential even after they presented a valid new one.
