HTTP authentication now handles a malformed success response from the authentication server (for example an invalid `acl` rule or `expire_at` value in an `"allow"` response) as a backend failure, the same way as an unparseable body or an unexpected status code. Previously EMQX replied to the client with CONNACK reason code 0x86 (Bad User Name or Password; return code 4 for MQTT 3.1.1 clients), which wrongly suggested the client's credentials were incorrect. Clients now receive 0x87 (Not Authorized; return code 5 for MQTT 3.1.1 clients) when the authentication chain denies the connection.
