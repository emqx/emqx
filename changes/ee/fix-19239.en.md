Fixed the WebSocket listener response for an unparseable `Sec-WebSocket-Protocol` header. Such a request now gets the same handling as a request without the header (a 400 reply when `fail_if_no_subprotocol` is enabled, an upgrade without subprotocol otherwise), in the WebSocket listener, the gateway WebSocket behavior and the OCPP gateway. Previously, the request process exited, the client got an empty 400 response, and a crash report was written to the log.
