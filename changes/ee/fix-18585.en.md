When a client whose session has Session Expiry Interval 0 was taken over by a new connection with the same client ID, the new connection could inherit the old session's subscriptions and queued messages. The MQTT 5.0 specification requires such a session to end when its network connection closes, so the takeover now ends the old session completely: the new connection starts a fresh session and receives CONNACK with Session Present 0. The old connection still receives DISCONNECT with reason code 0x8E (Session taken over), and its will message, if any, is published.
