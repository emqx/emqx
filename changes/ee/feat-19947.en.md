Improved TLS connection setup to avoid overloading a shared supervisor process when many TLS clients connect at the same time.

Before this change, one shared supervisor of the Erlang `ssl` application started all TLS connections, one at a time.
During a burst of TLS connections, for example after a network outage, the queue of that supervisor could grow faster than it emptied, and new TLS connections failed.
Now each TLS connection is started by its own connection process, so connections start in parallel.
