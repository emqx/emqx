Database authentication backends can now return client attributes, which previously only the HTTP backend could do.

MySQL, PostgreSQL, Redis and MongoDB authentication queries can now set `client_attrs`, so attributes stored next to the credentials become available to authorization rules and topic templates without standing up an external authentication service. A column or field aliased to `client_attrs.<name>` becomes one attribute, for example `SELECT password_hash, salt, sn AS "client_attrs.sn" FROM mqtt_user WHERE username = ${username}`, and a `client_attrs` field holding a map (a MongoDB subdocument) is taken as a whole. Redis authentication commands accept `client_attrs.<name>` fields alongside the existing ones.

Attribute values are no longer required to be strings. A value that is a number or a boolean is converted, and one with no string representation, such as a NULL column, is dropped with a log message instead of failing the authentication.
