MQTT WebSocket listeners gained a new `proxy_address_allow` option specifying which sources are trusted to carry the original client address and port in the `proxy_address_header` and `proxy_port_header` headers (typically the load balancers or reverse proxies in front of EMQX). The listener derives the client address from the forwarded header only for connections coming from trusted sources; otherwise the socket source address is used.

The value is either a list of IPv4 or IPv6 CIDR ranges, or `per_security_profile` (the default): in the legacy security profile all sources are trusted, keeping the existing behavior, while in the hardened security profile none are, so forwarded headers are ignored until trusted ranges are configured.

When the header lists several addresses, entries are now scanned from right to left, skipping trusted intermediate proxies; the first entry outside the trusted ranges is used as the client address. When all entries are trusted (as under the legacy default), the leftmost entry is used, matching the previous behavior.
