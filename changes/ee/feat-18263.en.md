MQTT WebSocket listeners gained a new `proxy_address_allow` option: a list of IPv4 or IPv6 CIDR ranges declaring the sources (typically load balancers or reverse proxies) trusted to carry the original client address and port in the `proxy_address_header` and `proxy_port_header` headers. The listener derives the client address from these headers only for connections coming from the listed ranges; otherwise the socket source address is used.

The default value `["0.0.0.0/0"]` keeps the existing behavior for IPv4 connections. It does not cover IPv6 sources: to honor forwarded headers on connections arriving over IPv6, add the proxy's IPv6 range (for example `::/0`) to the list.
