MQTT WebSocket listeners gained a new `proxy_address_allow` option: a list of IPv4 or IPv6 CIDR ranges declaring the sources (typically load balancers or reverse proxies) trusted to carry the original client address and port in the `proxy_address_header` and `proxy_port_header` headers. The listener derives the client address from the forwarded header only for connections coming from the listed ranges; otherwise the socket source address is used.

When the header lists several addresses, entries are now scanned from right to left, skipping intermediate proxies that are themselves within the listed ranges; the first entry outside the ranges is used as the client address. Previously the leftmost entry was always used; that behavior is preserved when all entries are within the listed ranges.

The default depends on the security profile. In the legacy profile, the default `["0.0.0.0/0"]` keeps the existing behavior for IPv4 connections; it does not cover IPv6 sources, so add the proxy's IPv6 range (for example `::/0`) to honor forwarded headers over IPv6. In the hardened profile, the default is `[]`, meaning forwarded headers are ignored until trusted ranges are configured.
