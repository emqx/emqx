Added the `node.pinned_plugins` setting. It lists plugins that a node runs independently of the cluster plugin config, for example plugins that are built into a container image.

Set it to a comma-separated list of name-vsns, for example `EMQX_NODE__PINNED_PLUGINS="my_plugin-1.0.0"`, or to an array. A pinned plugin runs from the directory `<plugins.install_dir>/<name-vsn>`, which must already hold the extracted package, for example in the container image. It is always enabled, and needs no `plugins.states` entry, no `plugins allow` grant and no install command. Its files and config are never copied from or to other nodes. Its config is the package default, merged with `etc/plugins/<name>.hocon` when that file exists. The config can be changed through the API or the Dashboard like for other plugins. A saved config is stored in `data/plugins/<name>/config.hocon`, and from then on that file is the whole config. The change applies on the nodes that run that plugin version. The plugin's own API endpoints under `/api/v5/plugin_api/` work as for other plugins. The node ignores `plugins.states` entries for the same plugin name, and cluster-wide plugin operations from other nodes skip it. When a pinned plugin directory is missing or the plugin fails to start, the node logs an error, raises an alarm, and keeps running.

`GET /api/v5/plugins` and `GET /api/v5/plugins/{name}` return a `pinned` flag for each plugin and for each node in `running_status`. Only the CLI can stop and start a pinned plugin, with `emqx ctl plugins stop|start|restart` on the node that pins it. A stop lasts until the node starts all its plugins again, at boot or after a cluster join. On the node that pins a plugin, the API returns HTTP 409 with the code `PLUGIN_PINNED` for the plugin's lifecycle operations: install, uninstall, start, stop, boot order change and cluster sync.

Nodes can now run different versions of the same plugin. The plugin must then stay compatible across these versions, for example in shared database tables, in RPC between its instances, and in its config.
