Fixed a crash of an MQTT over WebSocket connection process, and the loss of queued messages, when a client with a persistent session reconnected twice in quick succession. If the second connection tried to take the session over before the first had finished resuming it, the messages pending from the original connection were lost, and the first connection process crashed with a `function_clause` error in `maybe_resume_session`. Now the second connection is refused with CONNACK reason code `server_busy` (reason string `SESSION_RESUMING`), and the client can reconnect once the session is resumed.
