The cluster link health check now verifies the connection to the remote broker end to end: it sends an MQTT `PINGREQ` and waits for the `PINGRESP`, bounded by the link's `resource_opts.health_check_interval` / `health_check_timeout`, instead of only inspecting the local client state.  A link whose packets are silently dropped is now reported as `connecting` within a couple of health check intervals, so its buffer workers stop sending and keep the messages queued until the connection can be used again, and the resource alarm is raised.  Previously the link could stay `connected` until the client's own keepalive noticed the silence (1 to 2 x `keepalive`, 60 s by default), and traffic on the link made the client skip those keepalive `PINGREQ`s altogether; link clients now set `force_ping`, so their keepalive probes are always sent.
