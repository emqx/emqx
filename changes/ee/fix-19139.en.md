The cluster link health check now verifies the connection to the remote broker end to end: it sends an MQTT `PINGREQ` and waits for the `PINGRESP` instead of only inspecting the local client state.  A link whose packets are silently dropped is reported as `disconnected` as soon as the probe goes unanswered, so its buffer workers keep the messages queued and the resource is restarted, instead of the link staying `connected` until the client's own keepalive noticed the silence (1 to 2 x `keepalive`, 60 s by default), which ongoing traffic could skip altogether.  The message forwarding clients of a link are no longer configured with a client keepalive, as the health check replaces it.
