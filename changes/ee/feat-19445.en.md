Added Sparkplug Aware support to the Schema Registry, as section 10.1.4 of the Sparkplug 3.0 specification describes.

To enable this feature, set `schema_registry.sparkplugb.enable_sparkplug_awareness` to `true`. The default is `false`. This feature also needs retained messages to be enabled.

When the feature is enabled and EMQX receives an `NBIRTH` or `DBIRTH` message, it also publishes a copy of the message as a retained message with QoS 2. The copy has the same payload and goes to one of these topics:

- `$sparkplug/certificates/{namespace}/{group_id}/NBIRTH/{edge_node_id}`
- `$sparkplug/certificates/{namespace}/{group_id}/DBIRTH/{edge_node_id}/{device_id}`

A new `NBIRTH` or `DBIRTH` message from the same node or device replaces the retained copy. When the client has a mountpoint, EMQX adds it to the topic of the copy.

EMQX does not replace the timestamp in `NDEATH` messages.
