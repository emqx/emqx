Added the `mark_consumed` rule option. When no MQTT client subscribes to a message's topic, a rule with this option counts the messages it selects as delivered. The default is `false`.

A rule selects a message when its SQL yields a result, which is what the rule's `passed` metric counts. For such a message, MQTT 5 publishers get reason code 0 (Success) instead of 16 (No matching subscribers) in PUBACK and PUBREC, and the HTTP publish API returns 200 instead of 202. The message is counted in the new `messages.consumed` metric (`emqx_messages_consumed` in Prometheus) instead of `messages.dropped` and `messages.dropped.no_subscribers`, and no `$events/message/dropped` event is produced. Subscribers still receive the message. A namespaced rule marks only messages from its own namespace. When upgrading a cluster, set the option only after every node runs this version.

Plugins can mark a message the same way from a `message.publish` hook, and ExHook servers by setting the `message_consumed` header to `"true"` in the `OnMessagePublish` response.
