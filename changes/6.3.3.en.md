# 6.3.3

## Enhancements

- [#17917](https://github.com/emqx/emqx/pull/17917) Added a new plugin `emqx_bcast` that provides product-level device messaging APIs: `PubBroadcast` (broadcast to all online devices of a product), `BatchPub` (batch delivery to a device list with offline storage and QoS 1 acknowledgement tracking), and `RegisterMessage` (message pre-registration with content deduplication and TTL refresh).

  The plugin exposes a unified endpoint `POST /api/v5/plugin_api/emqx_bcast/pub`, delivers messages directly to connected client channels, replays pending QoS 1 deliveries on device reconnect, and exports Prometheus metrics at `GET /api/v5/plugin_api/emqx_bcast/metrics`.

  Plugin restart, index-owner handover, and core shutdown preserve queued delivery progress, per-device publication order, and the QoS 1 delivery ledger without requiring clients to republish or resubscribe.

- [#18843](https://github.com/emqx/emqx/pull/18843) Added a new API scope, `plugin_api`, that grants access to the plugin-extended API endpoints (`/plugin_api/...`) and nothing else.

  Assign it to an API key or a Dashboard user to let them call the endpoints a plugin publishes, without granting them the `system` scope, which is administrator-equivalent. The `plugin_api` scope does not grant plugin installation, start, stop or configuration — those stay in the `system` scope.

  Existing API keys and Dashboard users that hold the `system` scope keep their access to the plugin-extended API endpoints.

- [#18926](https://github.com/emqx/emqx/pull/18926) Added IPv6 support to the Kafka, Confluent and Azure Event Hubs connectors.

  - The connectors can connect to brokers at bracketed IPv6 addresses in `bootstrap_hosts`, for example `[::1]:9092` or `[fd00::5]:9092,host2:9093`.
  - The connectors can reach hostnames that resolve only to IPv6 addresses, and brokers that advertise IPv6 addresses.
  - The new `socket_opts.ip_family` option selects the IP address family. With the default `auto`, a hostname is tried over IPv4 first and then over IPv6. Set it to `ipv6` to connect over IPv6 only, or to `ipv4` to connect over IPv4 only.

  The upgraded Kafka client library also fixes a sync produce timeout. It could happen when SASL re-authentication ran while requests were still pending.

- [#19088](https://github.com/emqx/emqx/pull/19088) The `authentication_settings.ignore_backend_failures` and `authorization.ignore_backend_failures` settings now apply in both the `legacy` and `hardened` security profiles. Previously they took effect only under the `hardened` profile.

  Each setting now accepts three values:

  - `per_security_profile` (the new default): Follow the security profile. The `legacy` profile ignores backend failures. The `hardened` profile denies the client.
  - `true`: Ignore backend failures and continue to the next authenticator or authorization source.
  - `false`: Deny the client when a backend fails.

  Upgrade note: under the `legacy` profile, a stored value of `false` now denies the client on a backend failure. Saving the authorization settings through the REST API or the Dashboard in an earlier 6.x release can store `false` even if you did not change this setting. To keep the previous `legacy` behavior, set the value to `per_security_profile` after the upgrade.

- [#19096](https://github.com/emqx/emqx/pull/19096) Added the `mqtt.max_connect_packet_size` setting. It limits the size of a CONNECT packet, in addition to `mqtt.max_packet_size`. EMQX closes the connection of a client whose CONNECT packet is larger, and counts it under the listener shutdown counter `connect_packet_too_large`. The default is `1MB`, the same as the default `mqtt.max_packet_size`, so nothing changes until the setting is lowered.

- [#19126](https://github.com/emqx/emqx/pull/19126) Added support for publish hooks to report successful message persistence. The HTTP publish API returns HTTP 200 with the message ID when a plugin reports persistence, even when no subscription matches.

- [#19204](https://github.com/emqx/emqx/pull/19204) Added AWS IAM role credential support to Amazon Kinesis connectors.

  When both the access key ID and secret access key are omitted, EMQX obtains temporary credentials from an ECS task role or EC2 instance metadata and refreshes them before they expire.

- [#19217](https://github.com/emqx/emqx/pull/19217) Removed the 49.71-day upper limit on regular-message retention periods for Message Queues and Message Streams.

- [#19242](https://github.com/emqx/emqx/pull/19242) Added the `rpc.compress_level` and `rpc.compress_threshold` settings to compress the data that cluster nodes send to each other, including forwarded MQTT messages.

  `rpc.compress_level` sets the zlib level, from `1` (fastest) to `9` (smallest output). The default is `0`, which disables compression, so nothing changes on upgrade. `rpc.compress_threshold` sets the minimum packet size to compress and defaults to `1KB`.

  Compression uses CPU on both the sending and the receiving node to reduce the traffic between them. Enable it when the bandwidth between nodes is limited or billed, for example when a cluster spans availability zones. Level `1` gives most of the size reduction at the lowest CPU cost. For JSON payloads of 0.5 to 1 KB, level `1` reduced the traffic between nodes by about 60% and raised CPU usage by about 10% on the sending node and 5% on the receiving node. Payloads that are already compressed or encrypted do not get smaller, so for them compression only adds CPU cost.

- [#19359](https://github.com/emqx/emqx/pull/19359) Added the `node.pinned_plugins` setting. It lists plugins that a node runs independently of the cluster plugin config, for example plugins that are built into a container image.

  Set it to a comma-separated list of name-vsns, for example `EMQX_NODE__PINNED_PLUGINS="my_plugin-1.0.0"`, or to an array. A pinned plugin runs from the directory `<plugins.install_dir>/<name-vsn>`, which must already hold the extracted package, for example in the container image. It is always enabled, and needs no `plugins.states` entry, no `plugins allow` grant and no install command. Its files and config are never copied from or to other nodes. Its config is the package default, merged with `etc/plugins/<name>.hocon` when that file exists. The config can be changed through the API or the Dashboard like for other plugins. A saved config is stored in `data/plugins/<name>/config.hocon`, and from then on that file is the whole config. The change applies on the nodes that run that plugin version. The plugin's own API endpoints under `/api/v5/plugin_api/` work as for other plugins. The node ignores `plugins.states` entries for the same plugin name, and cluster-wide plugin operations from other nodes skip it. When a pinned plugin directory is missing or the plugin fails to start, the node logs an error, raises an alarm, and keeps running.

  `GET /api/v5/plugins` and `GET /api/v5/plugins/{name}` return a `pinned` flag for each plugin and for each node in `running_status`. Only the CLI can stop and start a pinned plugin, with `emqx ctl plugins stop|start|restart` on the node that pins it. A stop lasts until the node starts all its plugins again, at boot or after a cluster join. On the node that pins a plugin, the API returns HTTP 409 with the code `PLUGIN_PINNED` for the plugin's lifecycle operations: install, uninstall, start, stop, boot order change and cluster sync.

  Nodes can now run different versions of the same plugin. The plugin must then stay compatible across these versions, for example in shared database tables, in RPC between its instances, and in its config.

- [#19407](https://github.com/emqx/emqx/pull/19407) A QUIC connection now takes its hibernation timeout from `mqtt.hibernate_after` of the listener's zone, the same as a TCP or SSL connection. The control stream and the data streams of the connection both use this value.

  The QUIC listener setting `listeners.quic.<name>.ssl_options.hibernate_after` is deprecated. EMQX still accepts it in the configuration, but it has no effect. Before this change, the QUIC listener setting was in use, and a change of `mqtt.hibernate_after` had no effect on QUIC connections.

  Both settings default to `5s`. When neither setting was changed, the hibernation behavior of QUIC connections does not change.

- [#19544](https://github.com/emqx/emqx/pull/19544) Added the optional `region` field to the S3 connector and to the S3 exporter of file transfer. When it is set, requests and presigned URLs are signed with this region instead of the region inferred from the endpoint host.

  When `region` is not set, the region is now correctly inferred from AWS S3 interface VPC endpoint (PrivateLink) hosts, for example `bucket.vpce-1a2b3c4d-5e6f.s3.us-west-2.vpce.amazonaws.com`. Before this change, requests to such endpoints were signed with `us-east-1`, and AWS rejected requests to endpoints in other regions.

- [#19624](https://github.com/emqx/emqx/pull/19624) Introduce overload protection mechanisms for the durable storage write path.

  1. Monitor message queue length and drop old transactions when it exceeds a configured value.
  2. Limit the maximum number of operations in the transaction

- [#19642](https://github.com/emqx/emqx/pull/19642) Added the listener option `tcp_options.low_watermark` for the `gen_tcp` TCP backend.

  When the Erlang socket buffer of a connection grows beyond `high_watermark`, the socket becomes busy and stays busy until the buffer drains below `low_watermark`. Before this change, `low_watermark` was always the Erlang/OTP default of 4KB, so a connection that went busy at the default 1MB `high_watermark` stayed busy until almost all queued data was sent.

  When the option is not set, it defaults to a quarter of `high_watermark`, but never below `4KB`. This is the same ratio the `socket` TCP backend uses to clear congestion; that backend ignores the option. A value above `high_watermark` is clamped to `high_watermark`.

- [#19756](https://github.com/emqx/emqx/pull/19756) Added the `node.trusted_certs` configuration. It selects the CA certificates that outbound TLS clients trust when their own TLS configuration names no CA. The default `system_default` uses the CA bundle file of the operating system. Set `file:///absolute/path` to use a different PEM file.

  An outbound TLS client that sets `verify = verify_peer` and leaves `cacertfile` empty now verifies the server against these CA certificates. Before, such a client failed to connect.

  The built-in HTTP client that some integrations use (for example AI Completion, ClickHouse, OpenTSDB, TDengine, Tablestore, HTTP authentication and authorization, and S3) no longer has a CA bundle of its own. It uses `node.trusted_certs` too.

  An outbound TLS client can also set `cacertfile = system_default` to trust the CA certificates of `node.trusted_certs`. When `node.trusted_certs` finds no CA bundle file, the client uses the CA certificates that Erlang/OTP loads from the operating system. Listeners do not accept this value.

  The Docker image now installs the current Mozilla CA bundle from curl.se at build time.

  Relevant PRs: [#19756](https://github.com/emqx/emqx/pull/19756), [#19799](https://github.com/emqx/emqx/pull/19799).

- [#19775](https://github.com/emqx/emqx/pull/19775) Added the `dashboard.show_preview_version` setting. When it is set to `false`, the REST API reports the release version without the `-preview.N` suffix, for example `6.1.5` instead of `6.1.5-preview.1`. This applies to `GET /nodes`, `GET /nodes/:node`, the login responses and the API document. The default is `true`, which reports the version unchanged.

- [#19815](https://github.com/emqx/emqx/pull/19815) The `arrow_flight` driver in the Datalayers connector now uses `datalayers-adapter-erl` 0.1.6.

  Arrow Flight TLS connections verify the Datalayers server certificate. They default to
  `cacertfile = "system_default"` and `verify = verify_peer`. The `system_default` value uses the CA
  bundle from `node.trusted_certs`. A PEM CA path can replace the default. The connector
  rejects `verify_none`, client certificate settings, and `managed_certs`.

  The default `influxdb_v1` driver keeps its existing TLS behavior.

- [#19240](https://github.com/emqx/emqx/pull/19240) Reduced temporary memory allocation when receiving MQTT PUBLISH messages, without changing packet validation.

- [#19256](https://github.com/emqx/emqx/pull/19256) Bumped OTP version to 28.4.1-6 and builder version to 6.2-2.

  This reduces the memory used by each TLS connection: the per-connection ETS table for shared socket options is gone, and idle TLS 1.3 connections release their cipher state.

- [#19277](https://github.com/emqx/emqx/pull/19277) Reduced the memory used by each MQTT connection. Connections in the same zone now share one copy of the packet parser, serializer and zone settings instead of each keeping its own. With 10,000 idle TCP connections this saves about 170 bytes per connection.

- [#19278](https://github.com/emqx/emqx/pull/19278) Reduced memory usage for MQTT connections and external subscriptions.

- [#19419](https://github.com/emqx/emqx/pull/19419) Reduced the memory each connection occupies in the client information table. The table no longer stores the connection's socket term under `conninfo.sock`. Each entry is 16 bytes smaller for a TCP connection with the `gen_tcp` backend, 32 bytes smaller with the `socket` backend, and about 128 bytes smaller for a TLS connection.

  This changes the stored copy only. Hook callbacks receive the connection's own `conninfo`, which still carries `sock`. REST API responses are unchanged. Plugins that read the table directly, through `emqx_cm:get_chan_info/1,2`, `emqx_cm:lookup_client/1`, `emqx_mgmt:lookup_client/2`, `emqx_channel:info/1` or `emqx_connection:info/1`, no longer see `sock` under `conninfo`. Use `emqx_channel:info(conninfo, Channel)` in the connection process to read it.

- [#19420](https://github.com/emqx/emqx/pull/19420) Each TLS handshake no longer makes two calls to the file server to resolve the `cacertfile` path. Under a burst of TLS connections this removes the message backlog on the `file_server_2` process.

- [#19514](https://github.com/emqx/emqx/pull/19514) Reduced the CPU cost of handling PUBLISH packets.

  - Topic splitting and topic validation do less work for each message.
  - The Sparkplug B alias-mapping hook checks the topic first. It does no more work for topics outside the Sparkplug B namespace.
  - The A2A registry, schema validation, message transformation and legacy topic metrics add their message hooks only when the feature is first used. Before that, they add no cost to each message.
  - When no rate limit is configured for a client, the limiter configuration is not checked on each publish.

  In a test with 60,000 clients that each publish one 1 KB QoS 0 message per second, broker CPU usage dropped with both the `gen_tcp` and the `socket` backend.

- [#19554](https://github.com/emqx/emqx/pull/19554) Reduced memory retained by oversized socket buffers reused for smaller network reads. The default Erlang distribution and `gen_rpc` socket buffer sizes have been increased to 1088 KiB, above Erlang's reusable buffer limit.

- [#19556](https://github.com/emqx/emqx/pull/19556) A write to a cluster table now runs in a helper process only when the calling process has 100 or more messages queued, instead of 10. Under a high rate of new subscriptions, the broker workers that store routes crossed the old limit on one write in ten and waited for the helper each time, which added to SUBSCRIBE latency.

- [#19623](https://github.com/emqx/emqx/pull/19623) Improved Message Queue replay performance by skipping stored records older than the retention period when consumers start or recreate iterators. Saved acknowledgements are preserved.

- [#19627](https://github.com/emqx/emqx/pull/19627) Connections on a TCP listener with the `gen_tcp` backend no longer wait for the socket driver on every outgoing packet. This lowers broker CPU usage per message. In a 1-to-1 publish/subscribe benchmark with QoS 0, CPU usage per message was about 12% lower.

- [#19651](https://github.com/emqx/emqx/pull/19651) Keep the per-connection stats in an atomics array owned by the connection process instead of writing them to the `emqx_channel_info` table.

  Each row of the table now holds a reference to the array. The packet and message counters are incremented in place, so `GET /clients`, `GET /clients/{clientid}` and `emqx ctl clients show` report them as they happen instead of up to one stats interval late. The row is no longer rewritten after each `SUBACK` and on every stats timer tick, which removes a decompress-and-recompress of the row on each of those writes, and the counters no longer live on the heap of the connection process.

  The seven `seqno_q1_*` and `seqno_q2_*` fields of a durable session, which `GET /clients` and `GET /clients/{clientid}` showed with no consumer, are removed from the response. `n_streams` stays.

- [#19710](https://github.com/emqx/emqx/pull/19710) Topic matching no longer splits the topic into levels in these places:

  - shared-subscription topic matching;
  - the `topic_match` function of rule engine SQL and variform expressions;
  - the route updates of cluster links.

  The result is the same as before for a valid topic. The `topic_match` function takes runtime data, and a topic with a `#` level that is not the last level is not a valid topic. Such a topic now matches a filter with a trailing `#` where it did not match before. For example, `topic_match('#/a', '#')` now returns `true`.

  The default `acl.conf` now compares the `dashboard` username with an equality check instead of a regular expression.

- [#19718](https://github.com/emqx/emqx/pull/19718) An idle MQTT connection no longer wakes from hibernation at every keepalive check. It now wakes once, when the client is late by the keepalive deadline. The time to detect a client that is gone is unchanged. With many idle clients, the broker uses less CPU.

- [#19719](https://github.com/emqx/emqx/pull/19719) Reduced memory usage for in-memory sessions and the amount of session data copied during garbage collection.

- [#19732](https://github.com/emqx/emqx/pull/19732) Message publishing no longer calls into cluster linking on nodes where no cluster link is enabled.

- [#19733](https://github.com/emqx/emqx/pull/19733) Message delivery no longer reads the listener rate limiter configuration for each message when the listener has no delivery rate limit.

  A delivery rate limit that is added to a listener at runtime now applies to an existing client session within one statistics interval (`mqtt.idle_timeout`, 15 seconds by default), instead of on the next delivered message. A new client session is limited from its first delivered message, as before.

- [#19739](https://github.com/emqx/emqx/pull/19739) The broker no longer builds and publishes the `$SYS/brokers/<node>/clients/<clientid>/connected` and `.../disconnected` messages when nothing can receive them: no client in the cluster is subscribed to the topic, and the rule engine ignores `$SYS` messages (`rule_engine.ignore_sys_message = true`, the default). This saves about 4% of the broker CPU spent per connection.

  A subscriber on the topic still receives the event. With `rule_engine.ignore_sys_message = false` the messages are published as before, so a rule that selects from a `$SYS` topic still sees them. The same applies to the `subscribed` and `unsubscribed` client events, which are off by default.

- [#19740](https://github.com/emqx/emqx/pull/19740) Reduced the CPU cost of each client connection on a single-node deployment by about 7%. The session lock that EMQX takes on each CONNECT no longer sends an internal remote call to the local node when the cluster has only one node.

- [#19761](https://github.com/emqx/emqx/pull/19761) Reduced the memory each connection occupies in the client information table by the length of
  its client identifier and username.

  The table no longer stores the `clientid` and `username` entries under `conninfo` when they are
  equal to the ones under `clientinfo`, which it keeps. They still appear under `conninfo` when the
  CONNECT packet values differ from the ones the client ended up with, for example when the broker
  assigned the client identifier.

  This changes the stored copy only. Hook callbacks receive the connection's own connection
  information, which still carries both fields, and REST API responses are unchanged.

- [#19774](https://github.com/emqx/emqx/pull/19774) Reduced memory allocation and CPU overhead when delivering QoS 1 and QoS 2 messages through in-memory sessions.

  During rolling upgrades, inflight-message REST API pagination has two limitations:

  - Older nodes reject pagination cursors with HTTP 400 if successive REST requests switch from a 6.3.3 node to an older node.
  - After session takeover from a 6.3.3 node to an older node, inflight messages with the same microsecond delivery timestamp can be skipped if they span multiple pages.

  MQTT message delivery is unaffected.

- [#19785](https://github.com/emqx/emqx/pull/19785) Reduced memory retained by TCP connections using the `socket` backend. The new `tcp_options.buffer_retention_strategy` setting defaults to `packet`, which releases receive buffers while waiting for the next MQTT packet. Set it to `always` to keep the previous buffer retention behavior.

  Reads with a known packet length are limited to 16 MiB each. Larger packets are received in multiple reads.

- [#19790](https://github.com/emqx/emqx/pull/19790) Removed the count of socket receive and send operations from the per-client statistics.

  The per-client `recv_cnt` and `send_cnt` fields now show the number of MQTT packets received and sent, the same values as `recv_pkt` and `send_pkt`. Before, they showed the number of TCP packets. This applies to the `/clients` REST API, the `emqx ctl clients stats` CSV export, and the stored information of durable sessions. The fields are kept for compatibility.

- [#19800](https://github.com/emqx/emqx/pull/19800) Reduced CPU overhead and memory allocations when delivering MQTT messages to subscribers.

- [#19810](https://github.com/emqx/emqx/pull/19810) Reduced CPU overhead and temporary memory allocations when processing incoming MQTT messages.

- [#19811](https://github.com/emqx/emqx/pull/19811) Reduced the CPU cost of authorization checks with the file (ACL) authorization source and other rule-based sources. A check splits the topic into levels at most once, instead of once for each topic filter of the rules. A topic filter that starts with a fixed level, such as `$SYS/#`, causes no split when the topic starts with a different level.

## Bug Fixes

- [#16389](https://github.com/emqx/emqx/pull/16389) Fixed an issue where the OAuth2 `client_secret` was returned in plaintext by the configuration read APIs for authentication, authorization, gateways and HTTP connectors. It is now masked in API responses, and re-submitting the masked value keeps the stored secret unchanged.

- [#18810](https://github.com/emqx/emqx/pull/18810) Dashboard single sign-on now completes an OIDC or SAML login only in the browser that started it. EMQX gives each login a value, keeps it in a browser cookie, and matches it when the identity provider sends the browser back. A login that arrives in a different browser signs no one in.

  Three notes for operators:

  - Open the Dashboard at the address set in `dashboard_addr` before starting an SSO login. The identity provider sends the browser back to that address, and the cookie belongs to it.
  - SAML single sign-on now needs an `https` address in `dashboard_addr`. A SAML identity provider sends the browser back with a cross-site form post, and browsers carry the cookie on such a post only over HTTPS.
  - If browsers in your setup cannot keep the cookie and SSO login fails, set `skip_login_cookie_check = true` on the OIDC or SAML backend. This turns the browser check off for that backend, so enable it at your own risk.

- [#18834](https://github.com/emqx/emqx/pull/18834) Updated the `emqx` script to use the new HOCON CLI and improved the robustness of startup configuration generation when file operations fail, for example because the disk is full.

- [#18879](https://github.com/emqx/emqx/pull/18879) Audit records for requests denied by role-based access control now include the authenticated dashboard user or API key and the request's path parameters.

  Before this change, a request that passed authentication but was denied by role-based access control was recorded with an empty `source` and without `http_request.bindings`, so `GET /api/v5/audit` could not show who made the request or what it targeted. Records for unauthenticated requests are unchanged.

- [#18882](https://github.com/emqx/emqx/pull/18882) Aligned the WebSocket message size limit of MQTT and gateway listeners with the configured protocol limits.

  - On MQTT WebSocket listeners, `websocket.max_frame_size = infinity` (the default) now means twice the zone's `mqtt.max_packet_size`. Set an explicit value when clients send several MQTT packets in one WebSocket message.
  - On gateway WebSocket listeners, `websocket.max_frame_size` now takes effect. Its default is 2097152 (2 MiB), and the value `infinity` selects this default.
  - `websocket.max_frame_size` accepts values up to 268435455.

  The limit applies to a WebSocket message after its fragments are joined, and after decompression when `compress` is enabled. When a client sends a larger message, the connection is closed with WebSocket status code 1009.

- [#18883](https://github.com/emqx/emqx/pull/18883) Restricted the audit log to global users. The audit log records operations from every namespace, so only global administrators and global viewers can read it through `GET /api/v5/audit`. Dashboard users and API keys that belong to a namespace can no longer read it.

- [#18886](https://github.com/emqx/emqx/pull/18886) Reject invalid Backup Sync interval and timeout values, and suppress false-positive TLS certificate path errors for successful HTTP synchronizations.

- [#18945](https://github.com/emqx/emqx/pull/18945) Fixed the RocketMQ action's handling of a topic that does not exist on the broker.

  When the topic had no route on the name server and the broker did not auto-create topics (for example an Alibaba Cloud instance where topics are created per namespace in the console), every message was dropped with a `case_clause` error, and the whole message was written to the log each time. Now:

  - An action whose topic contains no placeholders is checked on every health check. When the topic does not exist, the action reports `disconnected` with a message that names the topic and the namespace, messages are held in the buffer and retried, and the action recovers on the first health check after the topic is created.
  - A message whose templated topic does not exist is dropped with a readable `topic_not_found` error, and the log no longer contains the message payload.
  - With a namespace configured, the auto-create default topic `TBW102` was requested as `<namespace>%TBW102`, which never exists, so topics could not be auto-created in a namespace. The default topic is now requested by its bare name, as the Java client does.

  Also fixed the connector alarm that was raised and cleared every two minutes while no producer was running: the name server closes an idle connection after 120 seconds, and the client now reconnects right away instead of reporting `connecting` for one health check.

- [#18957](https://github.com/emqx/emqx/pull/18957) Fixed a bug where uploading a plugin package from the Dashboard replied `ALREADY_INSTALLED` and refused to install it when the package tarball was already present in the plugin install directory but had not been unpacked. The upload now goes through the installation allow-list first, replying `403 FORBIDDEN` with the `emqx ctl plugins allow` instruction when the package is not authorized. Leftovers of an interrupted or failed installation (a directory without a readable `release.json`, or a manifest whose declared applications have not been unpacked) are no longer mistaken for an installation either: they are purged and the uploaded package is unpacked into a clean directory. An installation whose applications are still loaded is never purged: such an upload is refused with `plugin_is_in_use` and the plugin must be stopped first. A plugin installation attempt which is refused or which fails no longer deletes the package file it replaced, so the local copy of the installed package survives a refused upload and can still be used to repair the installation. An upload is refused when the package file it would replace can not be read, and a node where the plugin is already completely installed keeps the package which matches its files.

- [#18964](https://github.com/emqx/emqx/pull/18964) Fixed the SCRAM HTTP authentication backend rejecting the OAuth2 configuration that the Dashboard submits for it. Creating an `SCRAM` + `HTTP Server` authenticator with OAuth2 enabled now succeeds, and the access token is sent as a `Bearer` authorization header on the user lookup request.

- [#18987](https://github.com/emqx/emqx/pull/18987) Despite having the `resource_opts.health_check_timeout`, some Connectors/Actions/Sources did not actually use that value for timing out health checks.  This has been fixed.

  The affected integrations were:

  - Cassandra Connector
  - DynamoDB Connector
  - GCP PubSub Consumer Source
  - IoTDB Connector (Thrift driver)
  - Snowflake Aggregated Connector
  - SQLServer Connector
  - TDEngine Connector
  - MySQL Connector
  - Doris Connector
  - Postgres Connector

- [#19003](https://github.com/emqx/emqx/pull/19003) Hardened `PUT /api/v5/api_key/:name` so that it only updates the fields present in the request body.   Fixed HTTP actions ignoring `parameters.max_retries` in synchronous and asynchronous query modes. The parameter now controls retries within each action query, independently of retries performed by the action buffer. Existing free retries for normal connection shutdown races remain unchanged.

- [#19522](https://github.com/emqx/emqx/pull/19522) A client connection that is closed by the `force_shutdown` policy, because its message queue or heap is too large, no longer produces an error-level supervisor report. The listener shutdown counters now count these closures under `mailbox_overflow` or `proc_heap_too_large`. EMQX still logs each closure at warning level.

- [#19531](https://github.com/emqx/emqx/pull/19531) A TLS alert that closes an established connection no longer produces an error-level supervisor report. Each alert now increases a listener shutdown counter named by the alert kind, for example `user_canceled` or `bad_record_mac`, and is still logged, at notice level. Alert codes that the TLS stack does not recognize share one counter, `unsupported/unknown_alert`. Other socket errors that previously produced the same error report, such as an invalid proxy protocol header, are counted as `sock_error` and logged at notice level. The counters are shown by `emqx ctl listeners` and in the `emqx_client_disconnected_reason` Prometheus metric.

- [#19533](https://github.com/emqx/emqx/pull/19533) Fixed HTTP connectors using OAuth2 client credentials continuing to send a rejected cached token after an HTTP 401 response. The connector now refreshes the token and retries the request once, sharing refreshes across concurrent requests without resetting the configured HTTP retry budget. Failed token refreshes remain recoverable for buffered actions. This also applies to HTTP authentication and authorization.

- [#19546](https://github.com/emqx/emqx/pull/19546) Limit each LwM2M session to 1,000 pending downlink commands. When full, reject new commands with a 4.29 response over MQTT while preserving accepted commands in FIFO order. Report the pending count and fixed limit through mqueue statistics. Prevent repeated commands for the same path and type from growing the command-record eviction queue indefinitely.

  Use monotonic time for the LwM2M receive window so wall-clock adjustments cannot cause downlink commands to be sent to sleeping devices.

- [#19551](https://github.com/emqx/emqx/pull/19551) Fixed a race during Raft leadership changes that could crash a durable storage shard when a delayed transaction startup notification arrived while the transaction process was stopping.

- [#19556](https://github.com/emqx/emqx/pull/19556) Fixed etcd-based cluster discovery to survive a transient etcd outage. The node now reconnects to etcd with a backoff, and restores its own registration key after the connection comes back. Before this change the discovery process failed when etcd became unreachable, and the node stayed unregistered after etcd recovered.

- [#19560](https://github.com/emqx/emqx/pull/19560) Fixed a log formatter crash when a log handler sets `payload_encode = hidden`. Before this fix, a debug log event that carried a term field, for example the `data` field of the Cluster Linking `recv_data` event, was replaced by a `FORMATTER CRASH` report. Now the field is redacted as `Encoded(hidden)=******` and the log entry is written normally.

- [#19565](https://github.com/emqx/emqx/pull/19565) A malformed `Authorization` header now returns 401 `AUTHORIZATION_HEADER_ERROR` instead of a bare 400, and its content is no longer written to the error log.

  Credentials that the HTTP specification cannot parse, such as Basic credentials without the `:` separator or a Bearer token with an invalid character, previously made the request process exit. The crash report that followed held the header value at error level, so a client with a formatting mistake wrote its own credential to the log, and an unauthenticated caller could add a log entry of its own choosing on every request.

- [#19572](https://github.com/emqx/emqx/pull/19572) Fixed a problem where a durable session could hang upon failing to commit its state to the database.

- [#19574](https://github.com/emqx/emqx/pull/19574) Fixed publish-hook errors when client IDs containing MQTT wildcards were included in `$SYS` client event topics. The characters `#`, `+`, and `%` in client IDs are now encoded as `%23`, `%2B`, and `%25` in these topic names. Client IDs in event payloads remain unchanged.

- [#19581](https://github.com/emqx/emqx/pull/19581) Fixed a rolling upgrade that could stop with client sessions left on an old node. Nodes that run 5.8 to 5.10, 6.0.0 to 6.0.3, 6.1.0 to 6.1.4, 6.2.0 to 6.2.3 or 6.3.0 move sessions to other nodes during node evacuation with a call that 6.0.4, 6.1.5 and 6.3.1 no longer answered. - [#19582](https://github.com/emqx/emqx/pull/19582) Fixed MQTT-SN connection rejection reasons reported to hooks and logs. Consumers matching the misspelled reason must use the corrected name. The return codes sent to clients remain unchanged.

- [#19600](https://github.com/emqx/emqx/pull/19600) Fixed client certificate information being lost when a proxy terminates mutual TLS and re-encrypts the connection to EMQX. When a listener has `proxy_protocol = true` and the PROXY protocol v2 header carries SSL TLVs, EMQX now reads the client certificate details from the header. It reads the certificate from its own TLS session only when the header carries no certificate information. Before this change, a listener with TLS enabled always read its own TLS session, so a deployment that forwards the client common name through HAProxy lost it after an upgrade from 5.x.

  Also fixed several listener socket option problems: `v6only` and `{tune_buffer, false}` are now handled correctly, invalid socket tuning options are rejected instead of applied, and a fragmented PROXY protocol v1 header is now rejected instead of being parsed incorrectly.

- [#19608](https://github.com/emqx/emqx/pull/19608) Update the `emqx_bcast` plugin to `0.4.4`: preserve product isolation in the QoS1 trigger fallback, prevent promoter retries from recreating reclaimed deliveries, and use consistent content-derived IDs for RegisterMessage and inline BatchPub.

- [#19616](https://github.com/emqx/emqx/pull/19616) Fixed a crash loop in the license resource monitor when the license is temporarily not available. Before this fix, the monitor crashed and restarted at each check interval and logged an error each time. Now the monitor continues to run, and the license alarms continue to work when the license is available again.

- [#19618](https://github.com/emqx/emqx/pull/19618) Fixed a false `failed_to_read_data_file` warning during backup export. Only the log was wrong.

## Breaking Changes

- [#18788](https://github.com/emqx/emqx/pull/18788) Changed the default of `mq.auto_create` and `streams.auto_create` to disable automatic creation.

  Previously, subscribing to a `$queue/...` topic created a last-value message queue, and subscribing
  to a `$stream/...` topic created a last-value message stream, when the queue or stream did not exist.
  Both now default to `false`, so a subscription no longer creates anything implicitly.

  To keep the previous behaviour, enable automatic creation explicitly:

  ```
  mq.auto_create.lastvalue = {}
  streams.auto_create.lastvalue = {}
  ```

  Set `regular` instead of `lastvalue` to automatically create regular queues or streams. Only one of
  the two can be enabled at a time. Message queues and streams that already exist are not affected.

- [#18974](https://github.com/emqx/emqx/pull/18974) Added `mqtt.max_connect_user_properties`, which limits the number of MQTT v5 User Property pairs accepted separately in CONNECT properties and Will properties. The default is 100; set it to `infinity` to disable the limit.

- [#19774](https://github.com/emqx/emqx/pull/19774) For in-memory sessions, renamed the internal message header `deliver_begin_at` to `deliver_begin_at_us` and changed its timestamp unit from milliseconds to microseconds.

  Plugins and hook handlers that read this header must use the new name and adapt to the new precision.

- [#19910](https://github.com/emqx/emqx/pull/19910) Fixed an issue where the `heartbeat` configuration parameter of a RabbitMQ Connector would be multiplied by 1000 when sent to the RabbitMQ server.  This could lead to a connection being erroneously considered inactive and closed.
