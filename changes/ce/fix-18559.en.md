Fixed the SUBACK reason codes when a `client.subscribe` hook changes the number of topic filters.

A hook returning more filters than the client requested crashed the connection before any SUBACK was sent. A hook returning fewer reported the dropped filters as granted at QoS 0, so the client waited for messages on subscriptions that did not exist. Added topic filters now get no reason code, keeping one per requested filter in the order they were received, and dropped ones are reported as failed.
